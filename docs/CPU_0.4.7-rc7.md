# 0.4.7-rc7：撤回输出过渡，做等价 CPU 优化

rc6 的换音过渡、欠载淡出和恢复淡入已经全部删除。用户反馈网页正常、硬件密集演奏偶发爆音；此前没有实机耗时证据把原因锁定为换音突变，增加输出过渡不能解决处理器或外设等待造成的超时。因此先在提交 `0277f23` 恢复 rc5，再基于该实现优化重复计算。

## 实际改动

- 第三滤波器的串联全通单元每组展开四级，减少循环、索引和重复读取系数的指令。每一级的输入、乘法、截位、饱和及状态写入顺序保持原样；所有 2–24 级设置都保留。
- 包络速率和 LFO 步进系数按输入值缓存。键包含同步模式及 Beat，或自由速率 Speed 与调制的饱和求和值；变化时仍运行原计算。包络、LFO 相位继续逐采样推进，控制更新仍每 16 个输出采样执行。
- 输出和欠载处理恢复为 rc5 的原文件：正常块直接输出，欠载计数并输出常规静音块，后续 DSP 样本保持原顺序。

OSC、两倍内部采样、FM/Sync、矩阵、音符优先级、Mono/Legato、包络曲线及原始预设不变。效果器计算、Q23 混响、最终 +6.02 dB 增益和 MASTER 曲线保持 rc5 实现。没有重新基准化任何旧 PCM 或状态黄金值。

## 同条件性能比较

运行实际 `.fwsc` 的 pi32v2 指令，六个预设分别按住 A4，对照未修改 rc5 和 rc7。下表是每 256 帧的**模型平均 DSP 耗时**，并非设备实测。

| 预设 | rc5 | rc7 | 减少 |
|---|---:|---:|---:|
| Tresure Island | 3.220 ms | 3.212 ms | 0.26% |
| Primer | 2.247 ms | 2.239 ms | 0.37% |
| Ai no Labyrinth | 2.639 ms | 2.630 ms | 0.32% |
| Daisy Area 2 | 3.311 ms | 3.226 ms | 2.59% |
| Wanna Go To Hawaii | 2.561 ms | 2.552 ms | 0.33% |
| JUDD-ish 2000 | 2.208 ms | 2.200 ms | 0.38% |

Daisy 的 25 ms 密集音符序列，模型 DSP P99 从 3.482 ms 降至 3.397 ms，约减少 2.45%；峰值从 3.483 ms 降至 3.399 ms。Tresure 的重叠音符序列峰值从 3.389 ms 降至 3.381 ms，改善有限。不能用 P99 的采样差异夸大 Tresure 的计算收益。

假设为 240 MHz、普通指令 1 周期、除法 48 周期、SPI 外设 60 MHz。模拟器不模拟实际 cache、Flash、总线等待及连接的 USB 主机。六个持续音及两种密集序列的模型 UND/XRUN/DMA 均为 0；**这不能排除实机超时，也不能宣称实机爆音已解决。**

本轮还对函数边界和振荡器循环的编译方式做了比较；较慢的方案已排除。最终只有上述两项等价 DSP 改动。

## 尚未证实的实机原因

网页运行 C/WASM，不执行杰理指令、硬件中断和外设等待。网页没有爆音不能据此确认或排除设备 CPU 预算不足。当前没有设备连接，也没有爆音发生时的实际计时，因此硬件根因仍未确认。

这次只获得有限、可复现的计算节省。若实机仍出现爆音，需要将同一时段的 DSP MAX、XRUN、UND、DMA、CLIP 与输入/USB 中断耗时对照，区分队列耗尽、DMA 迟到和信号削波。现有 [设备性能采集页](https://rcell233.github.io/OpenIFW-fm1/diagnostics/) 可以读取这些计数，不需要硬件调试器。后续优化仍以实际瓶颈和音频一致性为依据。
