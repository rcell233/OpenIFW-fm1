# 0.4.7-rc1 实机验收

上一版 rc2 的实机 UI 已流畅，爆音未解决。当前实现、研究、模型假设及压力场景失败见 [研究报告](RESEARCH_0.4.7.md)。当前环境没有连接实体 FM-1，软件测试通过不构成实机验收。

在桌面 Chrome / Edge 打开 [安装页](https://rcell233.github.io/OpenIFW-fm1/install/?v=0.4.7-rc1)，确认显示 Install 0.4.7-rc1。保持 USB 连接，安装和重启时松开按键，尤其 OCT−。正常身份为 FM-1_982；FM-1_000 仍是救援，不算安装成功。可使用同页的 [0.4.6-rc2 回退](https://rcell233.github.io/OpenIFW-fm1/install/?recovery=0.4.6-rc2&v=0.4.7-rc1)，旧 0.4.4 / 0.4.1 也保留。

## 优先使用网页采集

安装完关闭安装器，在 [设备性能页](https://rcell233.github.io/OpenIFW-fm1/diagnostics/) 点击连接并允许 MIDI / SysEx，选择 FM-1 对应的输入和输出，开始十秒采集。同时正常演奏出问题的音色，转动旋钮和切页。采集结束可下载 JSON；原始 20 份设备快照都会保留。页面只读取统计，不改音色、输出模式或 Flash，也不清零计数。采集过程中如重置了计数，页面用最后一段汇总，原始快照仍保留。

测试六个工厂音色、按住旧音再按新音的 Legato、松开后回到仍按住的音、效果器尾音和 UI 连续操作，并记录破音发生在哪个音色、音高、耳机/模拟输出或 USB Audio。十秒采集不是长期稳定性的证明。

| 设备字段 | 含义与判断 |
| --- | --- |
| DSP MAX | 包含嵌套扫描中断与 MASTER 转换；扣除单独计量的 USB 供数时间。完整音频仍须在 5.805 ms 内完成 |
| IRQ MAX | 从 ALNK 入口到完整块提交及统计的耗时，包含 DSP、USB tap 和嵌套中断；本版与旧版仅复制音频的 IRQ 不可直接比较 |
| XRUN | 完整回调超过 5.805 ms 的次数；采集期间应不增长 |
| DMA / missed commit（屏幕 UND） | 已失去半区、出现新边界或剩余提交时间不足；保留上一个完整块。两项当前同时计数，应不增长 |
| CLIP / PEAK | 原始合成 PCM 的削波和峰值，在 MASTER 衰减之前测量；降低 MASTER 不能修复已经发生的内部削波 |
| 扫描 IRQ / USB 轮询峰值 | 实际 TIMER4 计量的高优先级输入服务和完整 USB 工作，用于区分 DSP 与外围中断负载 |
| USB Audio underrun / overrun / missed | 观察主机启用音频流时是否丢包或供数不足；不是模拟输出爆音的唯一原因 |
| DRAW / MAIN | 绘图耗时含音频抢占；主循环最长间隔用于判断操作响应，不能直接换算成 FPS |

如果听到破音而这些计数没有增长，仍不能认定正常；需结合实际输出方式与 CLIP/USB 数据继续查输出链路。模型没有真实 Flash/cache/bus 等待，也没有 USB 主机，本轮修复不能替代这份设备数据。

## 屏幕上的诊断

GLO → PERFORMANCE（或长按 HOME → SYS → PERFORMANCE）可 RESET 后查看上述主要音频计数。K1 的 SINE 是低电平 440 Hz，MUTE 为零，两者临时跳过 DSP；退出页面自动恢复 SYNTH，重启也默认 SYNTH，不保存到音色。

只有 SYNTH 破音可帮助缩小到合成/预算方向；SINE 也破音则要继续查 DMA、USB、外设或输出链路。它们是诊断线索，不能单凭一个模式正常就证明所有通路正确。

已知极端压力音色仍会超时并占满中断，当前版本尚未满足所有自定义 patch 的最坏情况实时要求。旧黄金音频、矩阵、包络和单音/Legato 结果不变，未通过丢弃合成块或隐式减载改变声音。
