# 0.4.7-rc5：修复混响弱音量化问题

**针对用户定位到 Reverb 的沙沙声，将混响延迟与反馈状态由 Q15 提升为 Q23。保留最终 +6.02 dB 输出、原空间结构及全部原始音色参数。软件测量确认量化误差明显降低；尚未在实体设备上确认嘶声是否消除。**

## 原因与改动

rc3 / rc4 使用简化的 Schroeder / Freeverb 类结构：22.05 kHz 下四个并联反馈 comb、两个串联 allpass，再取不同立体声抽头。旧延迟内存是 16 位，状态为 Q15。相等左右输入混为单声道后约为原幅度的 3%，弱信号进入 tank 时可能只剩几个或几十个量化台阶，反馈与阻尼还反复截断；后面的 ×4 / ×6 湿声校准会同时放大量化误差。这会产生与信号相关的粗糙残差，并截掉弱尾音。冷启动全零输入本身不产生随机白噪声。

新版保留归一化输入电平、延迟长度、反馈 / 阻尼系数、抽头增益、Size、HighDamp、Width 和 WetDry 的映射；只将延迟内存改为 32 位、信号状态增加八位小数精度。反馈乘法用有界 64 位乘积再移位，按零截断，避免负数一个 LSB 持续循环。实时循环没有新增除法、随机抖动、噪声门或堆分配。

这版先修精度问题，没有换成另一套混响拓扑；因此它仍是小型 room，而非完整 Freeverb 或 FDN。保留空间结构能将本次听感差异主要限制在弱音与衰减尾部。

## 增益安排

+6.02 dB 仍在效果器之后，与 MASTER 合并计算，最终饱和边界与 DAC 缩放不变。把这个增益移到 OSC 会改变 FM / 滤波 / Exciter 等非线性链路的驱动，影响音色；本次不这样处理。提高混响内部精度直接减少新增误差，最终线性增益则等比例放大已有信号和误差，无法恢复之前已丢失的小数位。

OSC、FM、同步、包络、LFO、矩阵、气息、单音 / Legato 代码和全部原始预设 JSON 不变；其他效果器算法、原 HAL、链接脚本、音频队列和显示调度不变。`synth.h` 只更改 FX 缓冲类型，不改变 916 字节 patch 格式。

直接运行生产 tank，对照相同延迟、相同量化系数的双精度实现。输入使用相同 Q20 数值，隔离 tank 内部新增误差。表中的误差包含相关量化失真，**不是硬件底噪、声学噪声或信噪比测量**。

- 196,608 个乘法边界 / 随机算术检查；与独立宽位除法参考完全一致，ASan / UBSan 无报错。
- 全零输入输出精确为零；40 秒信号与释音测试会衰减为精确零，没有持续极限环。
- Size 0 / 6.6 / 10 的脉冲尾音分别约 0.947 / 2.392 / 10.417 秒后归零。原 Q15 对应约 0.455 / 0.977 / 3.007 秒；增加的是过去被截断的弱尾部。首个湿声到达时间未变；相对原全速参考的 1 kHz 低通湿声能量仍在 ±3 dB 内。
- 六个预设共 288 个音高 / 力度 / 气息场景，最终输出无削波。满气息场景相对 rc4 的 RMS 变化最大 0.105 dB；部分低气息场景恢复原先被截掉的湿声，RMS 增加最多约 9.71 dB。后者不是新增输出增益，应在试音时关注弱吹与尾音的平衡。

- 72 个混响 / 音色余量场景无最终削波，普通构建与 ASan / UBSan 结果相同。

Daisy 的原始 EG1 → OSC4 NoiseLevel 调制保留；这部分有意合成的噪声不会被混响精度修复去除。软件结果只覆盖这些场景，不能代替模拟输出和任意用户音色的实机测量。

## 性能、启动与回归

实际执行交叉编译后的 pi32v2 固件指令：Daisy 持续 A4 运行 32 秒，UND / XRUN / DMA late 均为 0。DSP P99 为 3.354 ms，rc4 同场景为 3.327 ms，增加约 0.8%；最大 3.381 ms。UI 刷新间隔 P95 为 50 ms，主循环最大服务间隔 1 ms。超过 30 秒正常启动确认清零，OCT− 开机仍进入原 USB RESCUE。Tresure 的按键 / 释放场景也无欠载。

模型按 240 MHz、普通指令 1 周期、除法 48 周期、SPI 60 MHz 估算，不模拟真实 Flash / cache / 总线等待和 USB 主机，**不是实机 CPU 占用率测量**。

资源：data+bss 81,712 / 98,304 B；pool 285,208 / 344,064 B，比 rc4 增加 5,936 B；RAM code 19,176 / 24,576 B，增加 112 B；app 268,476 B，增加 128 B。原 HAL 和链接脚本 SHA-256 不变。正常固件独立重编译后，包、ELF、binary 与 metadata 完全一致。

原生 C 与目标指令流的 12 个湿 / 干声场景、196,608 帧、24 个哈希完全一致。未发布的 Q15 参考也与 rc3 / rc4 的原始流哈希完全一致。全速历史参考仍保留原 166 组 PCM / 状态 goldens；生产模式的 166 组音乐状态与 158 组干声保持精确一致。WASM / 原生 C 等价、UI、预设参数、最终 ×2 输出、安装器完整镜像传输与恢复测试一并运行；未重写历史音频基准。
