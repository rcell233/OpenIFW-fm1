# 0.4.6-rc1：音频调度与显示重做

0.4.5 已收到实机仍严重卡顿、逐行刷屏和爆音的反馈，先前的修复没有解决问题。本次撤掉丢块让出和逐行扫描设计，按单核生产者 / 消费者、有限中断工作量、非阻塞外设和区域重绘重新组织。**这是候选版；没有连接实体 FM-1，不能把软件通过当作实机验收。**

[安装 0.4.6-rc1](https://rcell233.github.io/OpenIFW-fm1/install/?v=0.4.6-rc1)。版本号应显示 `Install 0.4.6-rc1`。原始 [0.4.4 回退入口](https://rcell233.github.io/OpenIFW-fm1/install/?recovery=0.4.4&v=0.4.6-rc1) 和 0.4.1 包继续保留，救援身份 FM-1_000 仍不能通过正常安装确认。

## 审查结果与替换

| 已确认的代码问题 | 新实现 |
| --- | --- |
| 一次在 ALNK 中断中合成 256 帧，迟到后立即重入，主循环可能长期无法运行 | 主循环每次合成 32 帧；ALNK 只复制完整 PCM，并发送 USB Audio tap |
| 连续迟到后故意跳过一个 DSP 块，重复旧音频 | 删除该策略。每个合成样本按顺序计算；真正欠载时输出零并计入 UND |
| 16 行扫描多次执行同一页绘图，并对每一行计算哈希 | 标题、旋钮区、图形区、页脚按显示内容变化更新；图形区一次最多 128 行；删除行哈希 |
| USB 无响应时每秒重试，主循环忙等 25 ms | 复位 / 等待 / 连接状态机。等待期间主循环继续生产 PCM；软件复现的每秒音频欠载据此消失 |
| USB SIE 在高优先级中断中可能轮询 20,000 次 | 用 TIMER4 限定一次事务等待为 20 us，第一次失败后停止本轮轮询，由主循环重试 |
| MASTER ADC 同步轮询，LED 每次循环重复遍历映射 | ADC 异步采样；MASTER 每 10 ms 启动一次转换；LED 只在状态改变时写入 |

PCM 使用四个物理槽，通常只预排两个完整块，另有生产中的槽。主循环写完数据并执行 `csync` 才公布索引；中断完成复制才归还槽。DMA 仅读取独立的双缓冲区。两块预排会增加输入到声音的缓冲延迟，当前理论范围约 17–23 ms，尚未实测。

屏幕沿用原来的 SPI 时钟和 RGB565 格式，不承诺原子整屏切换。整屏物理传输本身在原来的时钟假设下约需 77 ms。音频队列充足时处理绘图；过载时后台动画等待，明确的按钮 / 旋钮操作保留服务机会。即使 DSP 不足以实时运行，设备仍应能接受操作和读取诊断。

## 热路径与构建

15,356 B 的逐采样热路径放进标准 `.audio_text` RAM 段，Flash driver 保留独立 `.ram_text` 段及“Flash 关闭期间不得调用 XIP”检查。链接器给出装载 / 运行地址，启动代码按原连续范围复制；构建逐字节核对装载镜像、复制长度、范围及热函数地址。小的 Flash / RAM 调用入口放在链接脚本明确的位置，以满足 pi32v2 的相对跳转范围。

构建脚本改为显式编译、链接、按 LMA 组合和打包；删除原来的编译器 / objcopy 函数替换。构建互斥锁防止不同测试变体覆盖同一暂存目录。应用按 `-O2`、DSP 按 `-O3` 编译。单核、原启动时钟，未依靠第二核或提频。

0.4.2 曾随 RAM DSP 改动出现救援启动反馈，但随后恢复 XIP 仍有同样问题；后续软件已复现长音频中断饿死看门狗的机制。这不能证明当时只有一个根因。本版重新验证正常 / OCT− 救援启动，并逐字检查实际执行的 RAM 复制结果；仍保留实体启动尚未验收的标记。

## 音色与验证

预设、参数、矩阵、调制更新顺序、振荡器的两倍内部采样、EG 曲线、单音 / Legato 和效果器结构保持原规则。新增的数值优化只包括稀疏清理已路由的调制目标、带溢出回退的精确插值、复用商计算余数及精确零输入路径。

- 166 个冻结场景的 332 份 PCM / 状态文件与 0.4.0 逐字节一致。
- 12 组网页演奏的 1,228,800 个立体声帧与冻结 WASM 音频一致。
- 32,768 帧、1,024 次实时改参数保持旧校验值；新增精确插值的随机与溢出回退检查。
- 57 页与独立同步画面逐像素一致，保留 8,120 组字体 / 线条 / 石纹对照，另测跨区域的菜单和命名文字修改。
- ASan / UBSan、USB 安装 / 恢复模拟、生产队列的欠载 / 阻塞 / DMA 所有权测试，以及 USB 重试和 SIE 故障注入纳入检查。

历史的中断丢块实现只保留在测试夹具，用于复现问题，发布固件不再引用它。

目标指令测试、构建 SHA 和完整结果见 [机器可读记录](evidence/rework-0.4.6-rc1.json)。指令模型使用 240 MHz、非除法一周期、除法 48 周期和 SPI 线速假设；**不是周期精确模型，不模拟真实 Flash/cache/总线等待，也没有连接 USB 主机。** RAM 放置不能在这个模型里证明真实加速。IRQ 的搬运耗时尤其不能当作 DSP 总成本下降的证据。

## 实机检查

进入 GLO → PERFORMANCE，RESET 后持续演奏并切页、转旋钮。`DSP MAX` 是一块的合成耗时，`IRQ MAX` 是搬运中断耗时；`XRUN / DMA / UND` 应保持 0。UND 增长表示完整 PCM 队列真的被耗尽，即使 DSP MAX 未超预算也不能称为通过。`MAIN` 是最大主循环服务间隔，单位 ms。SINE / MUTE 为诊断输出，退出该页恢复 SYNTH。

本次没有设备 FPS、真实音频回录或 USB Audio 并发实测数据；高负载自定义组合的计算需求也没有因重新调度而消失。候选版需要以实机声音、操作流畅度和这些计数共同验收。
