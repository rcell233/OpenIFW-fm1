# 0.4.2 硬件音频修复候选 · 2026-10-20

针对 0.4.1 在设备上的异常低沉声音和 UI 卡顿，本版修复音频 DMA 调度，并做保持数值一致的优化。开发环境没有连接实体 FM-1；本版已编译、通过软件验证，等待用户上板听音与计时确认。

## 改了什么

原 ISR 在合成结束后才清除 HALF 中断。运算稍微越过下一个边界时，这会同时清掉新事件，导致合成时钟骤降到一半；它还会在 DMA 缓冲中留下清零和 Q15 中间数据。相关基线复现保留在 [审查报告](HARDWARE_AUDIO_AUDIT.md)。

新 ISR 在入口确认当前事件，先将上一块已经算好、缩放完毕的音频以最终 Q24 格式发布，再在独立缓冲计算下一块。计算期间出现的新事件留待处理，不在出口清除。发布时检查半区所有权，跨边界就停止继续写入。新增固定一块（256 帧，约 **5.805 ms**）输出延迟；采样率仍为 44.1 kHz。

消除高频常数除法时，保留 C 的向零截断和所有饱和边界；没有用负数算术右移直接冒充有符号除法。目标编译把 **15,208 B** 热点 DSP 放入原有 RAM 代码区；连同独立审计的 Flash driver 共 **18,056 B / 24,576 B**。启动时复制范围、镜像中的加载字节和 PC guard 范围均检查。共享 UI 数学函数及冷配置代码保留在 XIP，符合 pi32v2 的直接分支范围。

显示改为每次主循环最多发送 16 行，输入和 MIDI 在各块之间处理。按行缓存校验值，跳过没有变化的行；绘制只执行与当前块相交的区域。页面布局、按钮和旋钮含义不变。57 个页面在冻结状态下与原同步绘制逐像素一致。

## 超时复现与保护

`tests/audio_deadline.py` 编译原平台 ISR；`--pipeline` 编译实际的新 `audio_output.h`。采样时钟驱动假 DMA，注入固定的计算耗时，不把该耗时当作实测性能。

| 注入计算耗时 | 0.4.1 合成进度 | 0.4.2 合成进度 |
| --- | ---: | ---: |
| 半区预算的 99% | 约 44.04 k 帧/秒 | 约 44.04 k 帧/秒 |
| 半区预算的 101% | 约 22.05 k 帧/秒 | 约 43.60 k 帧/秒 |

五档注入耗时下，新版 DMA 都没有读到中间格式的样本。按时完成时，440 Hz 信号保持原频率。持续超负载仍然会导致重复/缺失音频；缓冲保护不能替代足够的计算余量。此测试未模拟发布本身的总线耗时和 USB 并发；完整目标 ISR 另由下面的指令模型评估。

## 一致性与验证

- `make test`、`make sanitize`：原生 C / WASM、面板和 UI、安装器、ASan / UBSan。
- 166 场景、332 个 PCM / 状态文件与既有黄金数据逐字节一致；六个原始预设的 12 组演奏/切页音频共 1,228,800 个立体声帧继续匹配冻结的旧版 WASM。
- 1,098 个原始参数、192 个矩阵字段、120 个包络字段保持原值。Mono / Legato、EG、调制时序、内部过采样和效果器历史不变。
- 实际 pi32v2 指令执行的 12 个工厂干/湿场景共 196,608 帧，全部 24 个黄金校验值一致；分别采用除法耗时 1 与 48 周期的假设。
- 目标自测的 32,768 帧、1,024 次实时编辑匹配全部 16 个校验值；100,000 组随机运算及额外边界检查为 0 错误。
- 安装器检查实际发布包的 SHA、CRC、完整镜像传输和恢复/错误路径。软件测试没有刷写实体设备。

数值结果、固件 SHA 和模型假设保存在 [本版证据](evidence/hardware-audio-fix-0.4.2.json)。旧的音频黄金数据没有修改。

## 目标性能的解释

对最终发布包逐个运行六个工厂预设，各模拟 4.5 秒，包含 C4 / E4 重叠、松键回退和尾音。模型强制关闭 JIT，采用 240 MHz、非除法指令每条一周期、除法 48 周期，并启用按 60 MHz 外设时钟和 BAUD=4 计算的 SPI 线速。

| 工厂音色 | 完整 IRQ 峰值 | XRUN / DMA |
| --- | ---: | ---: |
| Tresure Island | 4.746 ms | 0 / 0 |
| Primer | 3.994 ms | 0 / 0 |
| Ai no Labyrinth | 4.345 ms | 0 / 0 |
| Daisy Area 2 | 4.811 ms | 0 / 0 |
| Wanna Go To Hawaii | 4.156 ms | 0 / 0 |
| JUDD-ish 2000 | 4.106 ms | 0 / 0 |

同假设的旧版首个预设峰值为 6.409 ms，本版为 4.746 ms。极端压力组合的稳定窗口峰值仍为 **7.491 ms**，超出预算，不能宣称所有自定义组合都可实时运行。实际目标输出的 SINE 检查为 **440 Hz**，MUTE 为全零。

**除法 48 周期是敏感性测试输入，不是芯片测量；此模拟器不精确模拟 CPU/cache/Flash/总线或连接的 USB 主机。** RAM 放置对实际 Flash 访问的改善也不能从该时间模型量化。真实表现请按 [上板步骤](HARDWARE_TEST.md) 验证，先看 SINE，再测 SYNTH、XRUN / DMA 和操作响应。

本版仍保留原设置和八度。如果只有机身键盘偏低，先在 GLO 确认 OCTAVE=3；外部 MIDI 60 不受机身八度设置影响。不要通过重置或改变预设来掩盖这个区别。
