# 机身 MIDI IN：接线与验证

rc14 的实机端只从 USB 接收队列取演奏消息，没有初始化机身 MIDI 插孔的 UART。浏览器通过 Web MIDI 收到电脑的控制器，是另外一条路径。rc15 增加机身输入，保留原 USB、合成器、连音与气息响应。

rc17 起，机身插孔接收的 CC5 会保留在原始录制中，但不进入合成器、气息映射或 MIDI Learn。换指时不会因吹管发送较大的 CC5 而拖慢滑音；原始音色与连奏行为保留。USB 输入继续支持 CC5，因此把原始 .mid 从电脑通过 USB 回放时，如需重现机身插孔行为，应过滤掉其中来自 TRS 的 CC5。

1. 电吹管的 **MIDI OUT → FM‑1 的 3.5 mm MIDI IN**；监听耳机或音箱接 FM‑1 的 **音频输出**。若吹管是五针 DIN 输出，需要对应 FM-1 接线的 DIN-to-TRS MIDI 转接线。输入无需连接电脑。
2. 到 GLO → CONTROL，先将 MIDI 接收通道设为 **ALL**。BR CC 选吹管实际发送的控制器编号：发送 CC2 就设为 2，发送 CC11 就设为 11；rc16 新设置默认为 CC2，既有已保存的编号保持不变。
3. 吹奏并换指。在 HOME 看音名是否变化，以及底部 IN/OUT 是否出现并随吹力变化。按键能发声只证明音频输出正常。音名跟着变但呼吸显示 `--`，优先检查吹管发的是哪种控制；气息数值会动但没有声音，确认吹管也发送了 Note On（只有 CC 不会触发音符）。如果两者都不动，用已知可接收机身 MIDI 的固件交叉验证同一条线和转接器。

## 实现与验证

- 使用 [Felucca 的 UART1 HAL](https://github.com/hugelton/Felucca/blob/ca1db43a78455ae747766a2738f8580380d40bc1/firmware/hal/fm1_uart.h)，PH8、31,250 baud，目标包校验该文件的 SHA-256。常规启动在 TIMER5 前配置；USB RESCUE 不启动串口。
- DMA 写入 512 字节对齐环形缓冲区。2 kHz 定时轮询只记录已完成的字节数；rc16 将 DMA 通知门槛从 32 字节降为 1 字节（不产生逐字节中断）。前台每次最多解析 32 字节，同 USB 一样交给现有的 MIDI 通道过滤、CC 路由和音频队列。音频中断不解析 MIDI。若长时间堵塞导致缓冲区可能被覆盖，会清掉残留状态和挂音，等新的状态字节重新同步。
- 支持连续状态（running status）、零力度 Note On、独立或交错的实时字节、弯音、控制器与节目信息。串口的时钟和 Active Sensing 不触发音符；SysEx 不送入 USB 更新器。解析出通道消息并不意味着合成器使用每一种控制类型。
- `make trs-input-test` 用模拟寄存器与 DMA 数据驱动实际 HAL 的读取顺序、前台、音符状态与 PCM 渲染；含通道过滤、CC2、延音、USB 共存、缓冲区回绕、过载恢复等。验证覆盖软件链路，不等同于实测 FM-1 的物理插孔、电缆极性和硬件时序。

另对六个出厂预设分别回放同一段吹奏，含连续呼吸、同帧换指和松音。串口原始字节路径与模拟 USB 消息路径得到的 184,320 帧立体声 PCM 逐字节相同。
