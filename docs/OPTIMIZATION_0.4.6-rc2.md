# 0.4.6-rc2：波形刷新与 DSP 计算优化

实机反馈：0.4.6-rc1 能启动，音色基本正确，但仍有破音，首页波形不再更新。这是 rc1 未通过声音和显示验收的证据。前一版的调度测试不能替代真实处理器的运行时间。

[安装 0.4.6-rc2](https://rcell233.github.io/OpenIFW-fm1/install/?v=0.4.6-rc2)。仍是候选版，未连接实体设备。0.4.4 和 0.4.1 的原始恢复包保留。

## 显示问题

rc1 仅在完整 PCM 队列达到两块时刷新后台波形。持续处于一块余量时，波形可以无限等待。新增的测试使用生产绘图函数、真实的目标端分支及模拟 DMA/队列状态，复现并防止该问题。

- 首页波形/动画使用 240×88 的局部区域，EG 电平使用 240×3 的局部区域；静态标题和参数卡不因波形变化而重画。范围包括波形的上下 ±43 像素端点。
- 队列达到两块时，后台更新最高 20 Hz；只剩一块时，保留最多 10 Hz 的刷新机会。队列空时后台绘图等待音频恢复。这里是调度上限，不能当作实机 FPS。
- DMA 未完成时立即返回，保留输入引起的重绘请求。不会在等待 DMA 时反复格式化四张参数卡、比较整份音色。
- 显示模型平时最高每秒检查 50 次；用户操作立即使其失效。按钮灯也按最终状态变化更新。

## 计算优化

所有四个振荡器仍以原来两倍内部采样率推进相位、同步和噪声；调制矩阵仍保持原来的顺序与更新频率。

1. 根据输出和矩阵引用规划实际需要的波形。只延后未被读取的纯波形计算。保存该采样实际使用的 FM 相位；切换音色、修改矩阵或读取诊断快照前，按旧的波形、脉宽和步长补出旧 CV，再更新参数。因此，新矩阵读到的仍是原引擎的上一采样值。
2. BLEP 的归一化除数只随振荡器步长变化时配置。用整数倒数乘法和一次余数修正，精确得到原来截断除法的商。没有降低 BLEP 精度或改成查近似值。
3. 合并 phaser 频率公式中可精确约掉的 Q16 比例，缓存只随音色变化的放大器深度与固定滑音速度，省掉已稳定的平滑计算和精确零贡献项。延迟插值用可证明有界的运算；溢出差值保留宽运算回退。
4. 对固定的四振荡器循环使用编译器的完整展开，去掉重复的索引、循环分支和仅第四个振荡器使用的条件，保留原执行顺序；构建检查展开后的代码仍在 RAM 段限额内。
5. 正弦、phaser、滤波和 EG 曲线的常量表通过链接器放到正常 `.data` RAM。启动代码按原来的 `.data` 复制方式搬运，构建检查表地址、容量和装载镜像；指令测试另检查复制后的每个字。表内容不变。

没有修改采样率、内部过采样倍数、预设、效果器结构、EG 曲线、单音/Legato、音符优先级或调制深度；没有启用第二核、提频或丢弃合成块。

## 验证

- 原有 166 场景、332 份 PCM/状态与冻结的 0.4.0 逐字节相同；原有实时编辑校验保持不变。
- 新增 65,536 帧、1,776 次不对齐采样块的音色编辑测试，校验声音、全部波形 CV、相位和最终效果器缓冲。参考值由未修改的 rc1 源码独立生成，记录在 `evidence/source-capture-rc1.json`。
- 整数运算随机检查包含缓存 BLEP、全部波形、按需掩码和满幅插值。主机测试同时运行 ASan/UBSan。
- 目标显示分支测试覆盖 DMA 忙时保存操作、一块队列下波形持续更新、上下端点、空队列暂停/恢复，并与完整重绘逐像素比较。
- 网页冻结演奏、57 页交互、USB 安装及原有音频队列/USB 故障注入检查保留。

构建身份、哈希、目标指令结果和比较数据见 [机器可读记录](evidence/optimization-0.4.6-rc2.json)。目标模型不模拟实际 Flash/cache/总线等待，也没有 USB 主机；尤其不能据此量化查表迁入 RAM 的实机收益。只把同条件比较用作软件证据，不把它写成实机 CPU 占用。

安装后进入 GLO → PERFORMANCE，RESET 后演奏并切页，查看 `DSP MAX`、`XRUN`、`DMA`、`UND`。`DSP` 才是合成成本；短 `IRQ` 只是搬运成本。`CLIP` 增长表示输出触顶；`UND` 增长表示 PCM 队列耗尽，二者需分开判断。实体声音和这些计数共同决定是否通过，rc2 目前没有实机通过结论。
