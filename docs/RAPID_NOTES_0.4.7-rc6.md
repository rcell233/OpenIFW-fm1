# 0.4.7-rc6：缓解密集换音与欠载边界的爆音

## 软件分析得到什么

快速换音不增加声部：仍是原来的单音引擎与四个 OSC。换音会让滑音、音高 / 滤波系数及部分缓存更频繁更新，负载可能略高，但目前的软件模型不能据此断言设备的偶发爆音一定由算力不足造成。

| 路径 | 本次证据 | 处理 |
| --- | --- | --- |
| 活动包络重触发或力度跳变 | 原 OpenIFW 的 Retrigger 会把包络归零。原生软件中 Daisy 密集重触发出现单采样输出突变；同期场景没有最终削波 | 在效果器后、MASTER 前，对实际发生这类事件的输出做短过渡 |
| 音频队列短时欠载 | rc5 驱动会在队列空时立即输出整块零；恢复时立即接上下一块。这两处可形成大幅边界跳变 | 从最后输出在 64 帧内淡到零，恢复后的首 64 帧从零淡入，UND 继续如实计数 |
| 设备实际耗时 / 外设等待 | 240 MHz 指令模型的快速断奏和重叠连奏均未复现欠载 | 保留现场诊断计数，不把模拟结果当作设备根因结论 |

慢速演奏时，前一个包络可能已经归零，新的起音更接近静音；密集重触发更容易在仍有信号时发生，因此这种突变会更明显。这里是代码与软件重现支持的解释，尚未取得实体设备的爆音录音或对应 UND / XRUN 记录。

## 改动与边界

`audio_transition.h` 使用固定长度的线性凸组合。只在 Note On 将重置非零包络，或活动音符的力度发生跳变时启用。第一帧接续上一个输出值，64 帧后恢复原始 PCM；没有重触发且力度不变的正常 Legato 保持原 PCM。首个静音起音不会额外触发此过渡，已有音频队列深度不变。极短重触发起音可能稍柔和。

引擎仍按原方式处理 Note On / Off、按键优先、重复音、松键返回、滑音、Retrigger、BR × EG、调制与所有效果器。OSC / FM / 同步、包络、矩阵、LFO、单音控制、预设、混响代码均未改动。过渡仅处理已经合成的输出，不修改这些内部状态，也不改变效果器反馈内的信号。

欠载时仍插入静音并记录 UND；保护不能恢复已经错过的输出时间，持续过载仍会听到中断。正常 DMA 路径逐字节保留；仅欠载 / 恢复边界使用一个 2 KiB 临时 PCM 缓冲。USB Audio tap 同时获得与 DAC 相同的淡出 / 淡入数据。每个 DSP 块继续按顺序生成、消费，不跳过或重放合成块。

短时逐采样平滑是常见的连续性处理方式，原理可参考 [JUCE Gain 的 ramp 文档](https://docs.juce.com/master/classjuce_1_1dsp_1_1Gain.html)。本项目实现为固定整数插值，不引入该框架。

## 软件验证

- **密集换音 18 个场景、4,147,200 帧**：六个预设 × 重叠换音 / 断奏 / 同音重触发，包含约 23 / 35 / 46 ms 的音符间隔。生产输出与关闭过渡的测试参考逐块对照；每块完整合成器状态和全部 FX 缓冲精确一致。1,704 个受保护事件的首采样边界跳变为零，64 帧之后恢复原 PCM，无最终削波。ASan / UBSan 与普通构建结果相同。
- **104,160 个插值检查**：端点、完整 0..64 权重及随机有符号 PCM，与独立 64 位有理数计算一致；1 / 7 / 31 / 32 / 64 / 256 帧分块一致，过渡中再次重触发也连续。受控 ±30,000 LSB 跳变从原先一步 60,000 降到每采样最多 938；这是测试信号的边界指标，不是音乐或硬件噪声降低的 dB 数。
- **生产驱动故障注入**：稳态 +30,000 → 欠载 → −30,000 的边界，原先最大跳变 30,000 LSB，新版最多 469。持续过载、40 ms 前台停顿、接近满载等八种调度输入检查：UND 如实增加，队列所有权、DSP 顺序及 DMA 内存边界保持正确，USB tap 与 DAC PCM 一致；ASan / UBSan 通过。
- **既有回归**：历史全速效果 / ×1 输出 / 无过渡的显式测试参考保留旧音频 goldens；生产引擎仍检查 166 组音乐状态与 158 组干声。288 个出厂场景、600 秒长场景与 72 个余量场景继续检查无输出削波；原生 C / WASM、最终 ×2 输出、面板与安装器一并回归。未重写历史音频基准。

## 目标固件与资源

执行实际交叉编译的 pi32v2 指令：

| 场景 | DSP P99 | DSP 最大 | UND / XRUN / DMA late |
| --- | ---: | ---: | --- |
| Daisy，25 ms 一次换音，6 秒 | 3.482 ms | 3.483 ms | 0 / 0 / 0 |
| Tresure，32 ms 一次重叠换音，6 秒 | 3.282 ms | 3.389 ms | 0 / 0 / 0 |
| Daisy 持续 A4，32 秒 | 3.354 ms | 3.382 ms | 0 / 0 / 0 |

Daisy 快速场景实际触发 159 次输出过渡；Tresure 重叠场景没有包络重触发和力度变化，触发数为 0。rc5 同快速 Daisy 场景 P99 为 3.482 ms，本次额外计算开销在模型中很小，不能据此宣传实机提速。

32 秒场景 UI 刷新 P95 为 50 ms，主循环最大服务间隔 1 ms，超过 30 秒后启动 pending 清零；OCT− 开机仍进入 USB RESCUE。另把模型频率强制降到 120 MHz 制造过载：出现 86 次 UND、582 次 DSP 超预算，DMA late 为 0，实际编译的欠载 / 恢复分支正常运行，没有模拟器 CPU 异常。这是故障注入结果，不是实际设备性能。

模型使用普通指令 1 周期、除法 48 周期、SPI 60 MHz 等假设，不模拟真实 Flash / cache / 总线等待和 USB 主机，**不是实机 CPU 时序测量**。

data+bss 为 83,808 / 98,304 B，比 rc5 增加 2,096 B；pool 保持 285,208 / 344,064 B；RAM code 保持 19,176 / 24,576 B；app 为 268,636 B，增加 160 B。原 HAL、链接脚本、Flash 分区、设置格式和音频队列深度保持不变。
